## 決定 1：執行環境——安裝 Python 3.12

- **狀況**：這台電腦的 PATH 上沒有 Python 也沒有 Node（`python3` 只是 Microsoft Store 的捷徑），只有 git。
- **選項**：(a) 裝 Python；(b) 完全不裝，假資料產生器用 PowerShell 寫；(c) 用 Gino 已有的 Python；(d) 裝 Node.js。
- **選了**：(a)。這是問過 Gino 後他選的。用 `winget install Python.Python.3.12 --scope user` 安裝（只裝給目前使用者）。
- **為什麼**：`data/make_sample.py` 已經是 Python，Gino 讀得懂；產生器要能被我實際執行和測試。
- **附帶**：在專案裡建了 `.venv/` 並裝了 pandas，只用來驗證偵察報告裡的資料數字。介面和 `make_mock.py` 都只用標準函式庫，不需要 pandas。

## 決定 2：技術——純 HTML + CSS + JavaScript，不用框架、不用建置

- **選項**：
  - (a) 純靜態網頁，資料用 `fetch` 讀 JSON，`python -m http.server` 啟動。
  - (b) Vite + React 或 Vue。
  - (c) Python 的 Streamlit 或 Plotly Dash。
- **選了**：(a)。
- **為什麼**：
  - 安裝最簡單：有 Python 就能跑，沒有 `node_modules`，不用連網路，展示現場不會因為套件壞掉。
  - Gino 讀得懂、改得動：三個 JS 檔共約 680 行，沒有框架的特殊語法。每個函式回傳一段 HTML 字串，可以整段複製去問別的 AI。
  - (c) 的版面和動畫受限，做不出「教室回放＋抽屜」這種互動，而且每次點擊都要重跑 Python。
  - (b) 功能最強，但多一層建置工具，對這個大小的原型沒有必要。
- **代價**：每次狀態改變就把整個分頁的 HTML 重畫一次。資料很小（16 人 × 30 張），不會慢；如果之後變成幾百個學生就要改。
- **不能直接雙擊 index.html**：瀏覽器不讓 `file://` 的網頁讀 JSON。考慮過把資料包成 `.js` 檔來避開，但那樣「介面只讀資料檔」就不成立了，之後接真資料也要多一步轉檔，所以沒這樣做。改成附 `start.bat`。

## 決定 4：誠實的畫面規則

- **問題**：想法泡泡很吸引人，但只是 AI 的說法；答對率才是可以驗證的。兩者放在同一個畫面，觀眾會一視同仁。
- **選了**三層標示：
  1. **實心標記＋「可驗證」標籤**：作答對錯、答對率。
  2. **虛線框＋「AI 說法・無法驗證」標籤**：想法、理由、懂／困惑／卡住。
  3. **MOCK 黃色斜紋標籤**：資料來源含 `MOCK` 時，出現在頂部（整句說明）、每個用到模擬資料的區塊、學生面板。另外檔名以 `MOCK_` 開頭、檔案裡 `"source": "MOCK"`、假的自由作答文字本身也寫「（MOCK：答錯的自由作答）」。
- **真實資料人數太少時也要誠實**：真實答對率旁邊畫 95% 區間（Wilson 區間）；真實人數少於 8 人時結論列出現紅字警告。高中版每堂只有 2–5 人，不畫區間會讓人以為那些數字很可靠。

詳見 `data_format.md`。加了 `format_version`、`step`、`revealed_qids`、`settings.seed`，另外新增 `data/sim/index.json` 當清單。

## 決定 6：假資料怎麼編

- **要求**：跟真實答對率有點相關但不完全一樣，要能展示「像」和「不像」兩種情況。
- **做法**（`data/make_mock.py`）：
  - 每題的假難度 = 真實答對率（轉成 logit）× fidelity ＋ 全班偏差 bias ＋ 雜訊。
  - `fidelity` 每堂課從 0.1 到 0.9 隨機挑，所以有的課很像、有的不像。
  - 學生有能力值，投影片狀態和答題用同一個能力值，所以「在某張卡住的人，對應的題目比較容易錯」。
  - 固定亂數種子，重跑結果一樣。
- **試過沒成功的**：第一版 fidelity 是 0.2–1.0、雜訊較小，結果 24 堂裡大部分 r 在 0.85 以上（高中第 5 堂 r = 1.00），而且 80% 以上的格子都是「懂」，畫面很無聊也太好看。改成降低 fidelity、加大雜訊、加入全班偏差、調低投影片的容易度之後，r 分布在 −0.01 到 1.00 之間，「懂」降到 62–83%。
- **第 2 步的假資料**：比較前 3 題的假模擬和真實答對率，把全班能力往真實方向平移 70%，其他都不變（用同一組亂數）。**結果不保證變好**：24 堂裡有些堂平均差距變小（例：小學第 10 堂 25 → 11 個百分點），有些變大。我沒有為了好看去調它——真的方法也可能這樣，畫面應該能呈現兩種情況。
- **已知的怪現象**：小學第 1 堂的假資料說投影片 2（大綱頁）最多人沒聽懂。原因是真實資料把 Q7 標到投影片 2（標記問題，見偵察報告 D3），假資料跟著題目難度走。保留它，因為它剛好示範了標記錯誤會造成什麼。

## 決定 7：「卡點」怎麼定義

- **模擬的卡點**：某張投影片上 `confused` 或 `lost` 的學生比例。
  - 考慮過只算 `lost`；但假資料裡 lost 很少，而且「困惑」也是老師想知道的。這是一個需要 Gino 決定的定義（見 `open_questions.md`）。
- **真實的卡點**：資料裡沒有課中行為（注視、困惑）資料，只能從課後測推：某張投影片的答錯率 = 1 − 對應題目課後答對率的平均。
  - 只有 35% 的投影片有對應題目，其他的畫成灰色斜紋「沒有真實資料」，不補值。
- **比較方式**：只在「有題目的投影片」裡各取最卡的 3 張，看重疊幾張。考慮過讓模擬在全部投影片裡取前 3，但那樣模擬選到沒題目的投影片時永遠對不上，不公平。
- **兩排的單位不同**（狀態比例 vs 答錯率），畫面上有一行字提醒：比的是哪幾張比較深，不是數字大小。所以兩排各用一個顏色的深淺，不共用色階。

## 決定 8：「像不像」怎麼算、門檻怎麼訂

- **指標**：每題模擬答對率和真實答對率的皮爾森相關係數 r；另外顯示平均差距（百分點）和「真實最難 3 題抓到幾題」。
  - 三個一起放，因為各有盲點：r 高但整體偏高 20 個百分點也可能；平均差距小但難題排序全錯也可能。
- **門檻**：r ≥ 0.7「像」、0.4–0.7「有點像」、< 0.4「不像」。**這是我自己訂的，沒有文獻依據**，滑鼠移上去會說明。一堂只有 6–12 題，r 本身很不穩。
- **算不出來的情況**：真實答對率每題都一樣時（高中第 8 堂，2 個學生全對），r 沒有定義，顯示「無法判斷」，並在難題清單上加警告。
- **同分怎麼排**：題號（或投影片編號）小的在前，結果才固定。

## 決定 9：顏色和圖表規則

- 照 Claude Code 內建的 dataviz 技能的參考色盤：模擬＝藍 `#2a78d6`、真實＝橘 `#eb6834`（色盤的第 1、2 色）；懂／困惑／卡住＝綠／黃／紅（狀態色）。
- **不只靠顏色**：模擬用圓形、真實用菱形；狀態一定搭配 ✓ ? ✕。色盲或黑白投影也分得出來。
- **色盤驗證工具沒跑**：那個工具要 Node，這台沒裝。我用的是參考色盤文件裡已經寫明通過驗證的相鄰色，沒有自己選新的顏色。
- **只做淺色主題**：投影機上淺底深字最清楚；多做一套深色要多驗一輪，對展示沒有幫助。
- **圖表用 HTML + CSS 自己畫，沒用圖表函式庫**：需要的圖（每題一列兩個點、格子熱圖、小柱子）用 `div` 加百分比定位就能畫，文字在任何解析度都清楚；用函式庫反而要學它的設定，也要多帶一個檔。

## 決定 16：視覺風格——像素風、從講台往後看的教室

Gino 在「像素風」和「小人走路的偽 3D／2D」之間還沒決定。我選了一個兩邊都沾到的做法先做出來：

- **像素風 ＋ 斜俯視（3/4 視角）**：地板、桌子有前後遮擋，看起來有深度，但全部是 2D 畫的。
- **鏡頭在老師背後**：學生面向我們，老師是畫面最下方的背影。
  - 考慮過「黑板在上方、學生背對我們」（比較像一般俯視遊戲），但那樣只看得到後腦勺。這個介面最重要的是**看學生的表情和頭上的符號**，所以讓學生正面朝鏡頭。
  - 代價：投影片不在場景裡，改放在右邊的「投影幕」面板。
- **小人會走路，但只在開場**：換一堂課時，學生從右上角的門走進來、各自走到座位坐下（約 4 秒，可以跳過）。上課中不讓他們走動——狀態資料是「每張投影片一個狀態」，走來走去不代表任何資料，反而讓人誤會。
- **坐著時的小動作對應狀態**：懂＝微笑、偶爾點頭；困惑＝歪嘴、歪頭、頭旁邊冒問號；卡住＝低頭、瞇眼、冒汗、頭旁邊冒漩渦；上一張不懂這一張懂了＝亮一下燈泡。
- **長相跟程度無關**：膚色、髮型、衣服是用學生編號算出來的（同一個編號每次長一樣）。故意不讓「程度較弱」的學生長得不一樣，避免觀眾用外表猜程度。
- **沒做真的偽 3D（等角視角）**：要畫的方向和遮擋多很多，對「看懂卡在哪」沒有幫助。Gino 想要的話可以再換（見 `open_questions.md` 第 10 題）。

## 決定 17：像素畫全部用程式畫，不用圖片素材、不用遊戲引擎

- **選項**：(a) 用 canvas 的 `fillRect` 一格一格畫；(b) 找免費的像素素材包；(c) 用 Phaser、PixiJS 這類遊戲引擎。
- **選了**：(a)，都在 `js/game/sprites.js`。
- **為什麼**：
  - (b) 要連網路找、要確認授權、期末展示和論文裡用還要標出處；而且素材的表情不會剛好有「困惑／卡住」。
  - (c) 這個場景只有 16 個坐著的小人，不需要物理、碰撞、鏡頭；引擎要多帶一個大檔，Gino 還要學它的寫法。
  - 自己畫的話，表情和符號可以完全照資料的三種狀態設計，圖例裡的小圖也是用同一段程式畫的，一定跟場景裡的一樣。
- **中文字不畫在 canvas 裡**：320×200 的像素畫布放不下清楚的中文。想法泡泡、名字用 HTML 疊在場景上面（`#overlay`），位置用百分比對齊小人。
- **試過沒成功的**：
  - 第一版把問號泡泡畫在頭的正上方，結果擋到後排同學的臉。改成畫在頭的右上方（欄與欄之間的空位）。
  - 第一版「答對」的圈是 5×7，看起來像數字 0，跟成績單的分數牌子搞混。改成 7×7 比較圓的圈。
  - 想法泡泡的進場動畫原本有淡入，無頭 Chrome 截圖時會卡在半透明。改成只有縮放、沒有淡入。

## 決定 18：一次只講一件事——時間軸、旁白、圖例

研究員版是「三個分頁，每頁很多東西」。觀眾版改成**一條時間軸**：① 上課（每張投影片一步）→ ② 課後測（每題一步）→ ③ 成績單。場景、右側面板、旁白都只講現在這一步。

- **旁白**（場景下方的深色對話框）：每一步用一句話說現在發生什麼事，例如「老師講到第 8 張……4 位困惑，1 位卡住」「模擬班 69% 答對，真實班 44% 答對——模擬班太樂觀」。觀眾不用自己讀圖。
- **圖例永遠在場景正下方**，而且跟著階段換（上課時解釋問號和漩渦，考試時解釋圈和叉）。右上角「？怎麼看」是完整說明。這是回應 Gino 說的「比較知道每個地方表示的意思」。
- **場景上一次只顯示一位學生的想法**（每 3.2 秒換一位，先輪卡住的、再輪困惑的）。研究員版是一次列 4 個。點學生就固定看他。

## 決定 21：觀眾版改用 `serve.py` 啟動（8000 埠被占用時自動換埠）

- **遇到的問題**：Gino 雙擊後開不起來。查到的原因：8000 埠上有一個下午 1:52 用 `start.bat` 開的舊伺服器還在（python 行程 6604），但它已經壞了——連得上，卻不回任何東西（`curl` 得到 "Empty reply from server"）。新的伺服器因為埠被占用開不起來，瀏覽器連到的是壞掉的那個。
  - 已驗證的：埠被占用、舊伺服器回空的、換一個埠就全部正常。
  - **不知道的**：舊伺服器為什麼壞掉。我猜是它的黑色視窗出了狀況，印紀錄失敗導致每個請求都失敗，但沒有驗證。
- **做法**：新增 `serve.py`（約 50 行，只用標準函式庫），`start_game.bat` 改成呼叫它。
  - 8000 被占用就試 8001、8002……，印出實際的網址並用那個網址開瀏覽器。
  - 不印每一筆請求的紀錄。
  - 叫瀏覽器不要快取，改了 JS／CSS 重新整理就看得到。
- **沒動的**：`start.bat`（研究員版的啟動檔）還是原本的寫法，有同樣的弱點。要不要一起換成 `serve.py`，等 Gino 決定。
- **我沒有做的**：沒有關掉那個舊伺服器（關別人開的行程被擋下來了，也應該由 Gino 自己關）。
